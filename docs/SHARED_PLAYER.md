# Shared controls — Viewsical 0.1.6

`PlayerControls.tsx` supplies transport, seeking, volume and settings for audio, video and docking. `PlayerOverlay.tsx` mounts only those controls, with no second application shell. Roboto, Lucide SVGs, translucent rounded menus, thin borders and shadow treatment are shared. CSS gradients replace the old ASS strips. The Lua renderer is removed from source and packaging.

The Rust overlay host lazily creates one transparent, frameless, shadowless WebView owned by the main window. It has no taskbar entry or global always-on-top flag. Physical bounds are calculated once in the main renderer, translated to screen coordinates natively, and deduplicated. Move, resize, DPI, focus, scroll and fullscreen transitions update geometry. Audio mode, bottom docking, dialogs, minimization, inactive ownership and shutdown hide it. Hidden initialization uses real bounds; only a successful local presentation handshake reveals the window. A slow initial handshake can recover from its timeout. Renderer failure exposes main-window keyboard controls and an explicit Retry controls action.

Only the bundled overlay origin/path can navigate this window. Its capability allows event listening plus presentation snapshots and typed playback actions. It cannot invoke account, browsing, download, storage or window commands. Snapshots contain stable metadata, player state, UI context, revision and loadId; cookies and temporary media URLs stay in Rust. Stale load actions fail. Queue navigation, fullscreen, theater and page scrolling go through the main coordinator.

Relative volume changes are serialized in Rust against the latest state and accept exactly ±5 points. The clamped result persists separately from normalization and mute. The shared shortcut classifier preserves editable/menu/dialog arrows and horizontal range controls. Normal key repetition is accepted; no second native mpv key handler is active.

Playback progress is broadcast at approximately 5 Hz; visible playing controls interpolate locally with requestAnimationFrame. Paused/hidden progress does not run an animation loop. Pointer leave dismisses menus immediately; active menus and gestures prevent the playing inactivity timer from hiding controls. Cancelled gestures and gestures spanning a load change do not seek.

At natural EOF mpv unloads the source. Seeking/toggling the final queue item reopens that same item at the requested position or zero, preserves mode and quality, and leaves queue identity unchanged. Local cache/download paths remain eligible and normalization is applied through the regular source commit.

## Verification

Automated results are under `artifacts/v016-*-results.json`. Native tests use isolated data and WebView profiles with real mpv decoding. The generated 120-second 1080p fixture has separate audio/video cache entries and +6 dB metadata, allowing exact -6 dB gain assertions without network variability. The EOF regression reaches natural EOF in a one-item audio queue, drags the real React range, and checks position, mode, queue count and gain. Browser tests cover both themes, outer scrolling, pagination, independent nested scrollbars, menus and layout densities 1/1.25/1.5/2.

Native composition, alignment, fullscreen, mini-player, docking and modal stacking are checked on this computer at its actual 125% Windows scale. Browser density emulation at the other scales is not native Windows DPI certification. The measured native menu response and 1080p frame-drop comparisons are recorded as observations, not a guarantee for other hardware. Transparent menus use CSS compositing; backdrop blur cannot sample native mpv pixels beneath another window.

Real anonymous YouTube playback, audio-only decoding and gain, full cache replay, completed audio downloads/offline playback, maximized restoration and clean restart are separately exercised by `scripts/v016-live-smoke.mjs`. No authentication UI or credentials are automated. The existing remembered sign-in profile and stable application identifier are retained.

Final checks: 59 Rust tests, 22 frontend unit tests, 16 shared-control browser checks, 40 scrolling/layout checks, 10 live playback/cache/download/restart checks, and 15 optimized native checks passed. The optimized native menu measured 6.8 ms p95 over 35 samples during 1080p playback. Decoder/output frame drops were zero in both ten-second hidden/visible samples. WebView2 process working sets rose from 391.7 MiB to 522.4 MiB after video/overlay startup, with one additional renderer. This approximately 130.7 MiB delta includes startup/shared-process allocations and is not an isolated allocation measurement for the menu. Native Windows keyboard injection confirmed 42 → 47 → 42 while paused; overlay keyboard routing and text/menu exclusions were checked separately.

Retry controls waits for Tauri to remove the destroyed window before reusing its label; testing found that immediate recreation could otherwise be skipped. The optimized check confirms one replacement overlay, unchanged playback load/gain, and clean app/mpv/WebView2 exit.

Release tests must not use the debug-only `TUBEDESK_DATA_DIR` override. The optimized native suite requires a separately compiled `app.viewsical.v016qa` identity, an explicit QA data directory, and verifies the identifier in the executable before launch. The actual portable package is checked separately for bundled UI/resources, single instance and clean closure. The existing account was also validated through ordinary startup without authentication UI automation.
